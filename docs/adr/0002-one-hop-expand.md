# ADR 0002: 一跳扩展不用 PageRank

- 状态: Accepted
- 日期: 2026-06-03
- 关联: 设计文档 D2 / 3.4 模块二 / ADR 0001

## Context

GraphRAG 的图谱扩展有不同实现路线：图算法（PageRank 迭代打分后取高分节点）或规则扩展（直接取共享实体的一跳邻居）。
PageRank 能衡量节点全局重要性，但需要全图迭代计算，延迟高、算法级别过高；
本场景目标只是"找到与命中 chunk 共享实体的关联 chunk"——一跳扩展。

## Decision

**一跳扩展不用 PageRank**：命中 chunk 的实体 → 查 relations 表关联实体 → 取关联实体所在 chunk。
一条 SQL JOIN 毫秒级响应，已解决跨文档关联核心问题；PageRank 收益边际递减，不引入。

## Consequences

正面:
- 延迟可控: 无迭代计算, 扩展路径固定为一跳.
- 结果可解释: 扩展依据是明确的实体共享关系, 非黑盒打分.
- 实现简单: 复用 graph_store 的 JOIN 查询, 无额外依赖.

负面:
- 对"重要但无直接共享实体"的 chunk 无法扩展(需要多跳/全局算法才可).
- 未来若扩展深度或图规模增长, 需重新评估(升级路径见 ADR 0001).
