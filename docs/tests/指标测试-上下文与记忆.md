## 三、测试用例与结果记录

### 用例 1: 跨会话记忆召回(核心验收)

**步骤**:
```bash
# 会话 A: 声明偏好(触发规则重要性 9 分, 需 LLM 打分的场景见用例 2)
curl -s -X POST http://localhost:8000/api/v1/chat \
  -H "Content-Type: application/json" \
  -d '{"user_id":"u1","message":"请记住我喜欢用 Markdown 写文档"}' | jq .
# 记录返回的 session_id 为 sid_a

# 手动沉淀(或再聊 4 轮触发自动沉淀): 会话 A 短期记忆 → 长期
curl -s -X POST http://localhost:8000/api/v1/memory/u1/sediment \
  -H "Content-Type: application/json" -d "{\"session_id\": $sid_a}" | jq .

# 查询长期记忆
curl -s http://localhost:8000/api/v1/memory/u1 | jq .

# 会话 B(新会话): 提问触发召回, 回答应体现"Markdown 偏好"
curl -s -X POST http://localhost:8000/api/v1/chat \
  -H "Content-Type: application/json" \
  -d '{"user_id":"u1","message":"以后帮我写文档用什么格式好?"}' | jq .
```

**预期**:
- 沉淀接口返回 `{"saved": 1}`
- `GET /memory/u1` 含 "请记住我喜欢用 Markdown 写文档", importance ≥ 6
- 会话 B 的回答体现用户偏好(如"按您的偏好使用 Markdown"), 或至少回答中带记忆段落

## 五、已知限制与说明

1. **召回质量依赖 embedding 模型**: 记忆向量召回需本地 `BAAI/bge-m3`(或 API embedding),
   模型未就绪时记忆照常入库(embedding=None), 召回退化为"重要性 + 新鲜度"排序, 无语义相关度。
2. **时间衰减权重**: 召回分数 = 0.7×相似度 + 0.2×重要性归一 + 0.1×新鲜度(1/(1+距上次召回天数/7)),
   last_recall 越近排序越占优("用进废退")。
3. **沉淀只筛选用户消息**: assistant 消息不沉淀(偏好/习惯通常由用户表达)。
4. **短期记忆 TTL**: Redis key `mem:short:{session_id}` 按 `session_ttl_seconds` 过期,
   过期未沉淀的消息丢失(会话级语义)。
5. **spiller 依赖沙盒就绪**: 卸载写入 MinIO, MinIO 不可用时超阈值文本直接截断(策略降级),
   不影响对话可用性。
